# E-Commerce API

A learning project: a REST API for a simple online store, built with Spring Boot.

The domain is the classic e-commerce model — users browse a product catalog, place orders, and each order holds line items that snapshot the product and its price at purchase time.

## Status

Work in progress. The **product catalog** is the only part exposed over HTTP so far. The `User`, `Order`, and `OrderItem` entities and their repositories exist in the database layer, but have no controllers or services yet. Authentication is not implemented — Spring Security is wired in but currently leaves `/product/**` open.

## Tech stack

| Piece | Choice |
|---|---|
| Language | Java 17 |
| Framework | Spring Boot 4.1.0 (Web MVC, Data JPA, Security, Validation) |
| Database | MySQL 8 (schema auto-created by Hibernate `ddl-auto=update`) |
| Build | Maven (`./mvnw`) |
| Boilerplate | Lombok |

## Project layout

```
src/main/java/com/apps/ecommerce/
├── config/       SecurityConfig — filter chain, BCrypt password encoder
├── controller/   ProductController — HTTP layer
├── dto/          ProductCreateRequest / ProductResponse (Java records)
├── entity/       Product, User, Order, OrderItem (JPA)
├── enums/        Role (USER, ADMIN), Status (PENDING, PAID, SHIPPED, CANCELLED)
├── exception/    Custom exceptions + GlobalExceptionHandler
├── repository/   Spring Data JPA repositories
└── service/      ProductService — business logic, entity ↔ DTO mapping
```

The layering is deliberate: controllers only handle HTTP, services own the logic and the entity↔DTO mapping, and repositories only touch the database. Entities never leave the service layer — the API speaks in DTOs.

## Data model

- **Product** — `id` (UUID), `name`, `price`, `stock`, `description`
- **User** — `id` (UUID), `email` (unique), `password` (BCrypt-hashed), `role`, `enabled`
- **Order** — `id` (UUID), owning `user`, `status`, `totalPrice`, `createdAt`, list of items. Table is named `orders` because `order` is a reserved SQL word.
- **OrderItem** — links an order to a product with `quantity` and `unitPrice`. The price is copied onto the line item so historical orders don't change when the catalog price changes.

All primary keys are UUIDs, generated by Hibernate.

## API

Base URL: `http://localhost:8080/api/v1` (the `/api/v1` context path is set in `application.properties`).

| Method | Path | Description |
|---|---|---|
| `GET` | `/product/all` | Paged list of products |
| `GET` | `/product/{id}` | One product by UUID |
| `POST` | `/product` | Create a product |
| `PUT` | `/product/{id}` | Replace a product |
| `DELETE` | `/product/{id}` | Delete a product |

`GET /product/all` accepts the standard Spring pagination query params — `page`, `size`, `sort`. It defaults to `size=20` sorted by `name`.

### Example

```bash
# list products
curl http://localhost:8080/api/v1/product/all

# create one
curl -X POST http://localhost:8080/api/v1/product \
  -H "Content-Type: application/json" \
  -d '{"name":"Keyboard","price":49.99,"stock":10,"description":"Mechanical, 60%"}'
```

### Error format

`GlobalExceptionHandler` turns exceptions into a consistent JSON body:

```json
{
  "status": 400,
  "message": "Not valid",
  "error": "...",
  "timestamp": "2026-08-07T12:00:00",
  "fields": { "name": "name is required" }
}
```

`fields` is only populated for validation errors; it is `null` otherwise.

| Situation | Status |
|---|---|
| `@Valid` failure on the request body | 400 |
| `ResourceNotFoundException` | 404 |
| `DuplicateResourceException` | 409 |
| Any other `RuntimeException` | 500 |

## Running it

**Prerequisites:** JDK 17+, and a MySQL server on `localhost:3306`. The connection URL uses `createDatabaseIfNotExist=true`, so the `ecommerce` schema is created on first run — you only need MySQL itself running.

Credentials live in `src/main/resources/application.properties`. Change `spring.datasource.username` / `password` to match your local MySQL before starting.

```bash
./mvnw spring-boot:run
```

The app starts on port 8080. Hibernate logs the SQL it runs (`spring.jpa.show-sql=true`), which is handy while learning.

To build a jar instead:

```bash
./mvnw clean package
java -jar target/ecommerce-0.0.1-SNAPSHOT.jar
```

## Notes and next steps

- Database credentials are committed in plain text in `application.properties`. Fine for local learning; move to environment variables or a `dev` profile before this goes anywhere real.
- CSRF is disabled and sessions are stateless — the setup anticipates JWT auth (see the commented-out `jwt.secret` properties), which isn't built yet.
- Planned: user registration and login, order placement, and stock decrement on purchase.
